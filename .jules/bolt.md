## 2024-05-19 - Fast-paths for smaller inner types in VarInt decoders
**Learning:** For variable length integers (VarInt), standard implementation will check if an exact byte marker corresponds to the destination type being decoded. E.g. when decoding a `u64`, the exact match checks for a `U64_BYTE`. If a number fits in a smaller representation, it uses a smaller marker (like `U16_BYTE` or `U32_BYTE`) but still decodes to `u64`. Without fast paths for these smaller markers, it must fallback to a generic `#[cold]` function call which is un-inlineable.
**Action:** By duplicating exact inline-able fast path checks for smaller marker sizes when decoding larger integer types, we can optimize `varint_decode_*` performance by removing fallback overhead. For instance, decoding a `u16`-sized number into a `u64` type improved by over 60%. Furthermore, for signed integer decoders, rather than duplicating all logic from unsigned variants or doing upcasting bounds-checks on an `i64` fallback, it is significantly faster to directly wrap and delegate to the equivalently-sized unsigned decoder and then apply inline ZigZag decoding locally (improving `isize` decoding performance).
