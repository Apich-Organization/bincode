## 2024-05-24 - bincode-next std::io::BufReader varint overhead

**Learning:** `std::io::BufReader<R>` implementation in `bincode-next` uses `peek_read` to rapidly decode varints. However, the default implementation of `peek_read` just does `self.buffer().get(..n)`. For larger varints (u32, u64, u128), if there aren't enough bytes in the current buffer, it falls back to a slow `.read` call rather than just calling `fill_buf()` to grab more data from the underlying reader into the buffer. This causes unnecessary overhead for standard integers when crossing a buffer boundary. Modifying `peek_read` to call `fill_buf()` when `self.buffer().len() < n` allows varints across boundaries to be decoded at full speed using unaligned pointer reads. The trait method needs to be called unambiguously with `std::io::BufRead::fill_buf(self)` instead of `self.fill_buf()` to avoid conflict with other methods.
**Action:** When implementing custom fast-path varint overrides via `Reader::peek_read`, be sure to explicitly fill the buffer if its length is less than `n` to avoid falling back to the slow, non-contiguous byte read paths. This also applies when modifying any buffer-backed `peek_read` logic.
