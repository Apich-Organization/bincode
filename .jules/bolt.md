## 2024-05-18 - Read Unaligned vs Byte Array Loading
**Learning:** In Rust, decoding integers using byte arrays (e.g., `u16::from_le_bytes(bytes)`) from a byte slice forces the compiler to assemble the values byte by byte in some non-optimal paths, incurring an unnecessary array allocation or load penalty. Conversely, reading memory directly via `core::ptr::read_unaligned` and calling native endian conversions (`u16::from_le(val)`) generates more optimal machine code by treating the read directly as integer loads, dramatically improving execution speed in tight decoding loops like varint processing.
**Action:** Always favor `core::ptr::read_unaligned` paired with `from_le`/`from_be` over array slicing with `from_le_bytes`/`from_be_bytes` in hot path code parsing binary formats, given we have proven the source buffer contains sufficient bounds safely.
