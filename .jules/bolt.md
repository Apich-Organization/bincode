
## 2024-10-04 - BufReader fast path optimization
**Learning:** `std::io::BufReader` does not automatically trigger `fill_buf()` when accessing its buffer via `buffer()`. If you're building a fast path that relies on looking at the internal buffer (like `peek_read` for custom `read_u*` overrides), and the current buffer length is less than needed, it might just fail to take the fast path instead of asking the underlying reader for more bytes. This can cause severe performance regressions (e.g. falling back to 1-byte reads). Also, due to NLL (Non-Lexical Lifetimes) limitations, placing conditional returns tied to `self` in an early branch fails to compile.
**Action:** When implementing `peek_read` for `std::io::BufReader`, explicitly check `if self.buffer().len() < n`, and if so, proactively call `<Self as std::io::BufRead>::fill_buf(self)` (ignoring the result so errors propagate properly down the normal read path). This guarantees the buffer is filled when needed without violating borrow checker rules: `if self.buffer().len() < n { let _ = <Self as std::io::BufRead>::fill_buf(self); } self.buffer().get(..n)`.
